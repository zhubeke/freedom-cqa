CQA checklist and appeal review redesign — delivery report
8 November 2026

Implemented directly in the existing Vue 3/TypeScript and Fastify application. Existing working-tree changes were preserved. The project uses its existing custom Vue controls rather than PrimeVue; no replacement UI framework or new dependency was introduced. Dragging uses the existing vue-draggable-plus/SortableJS dependency.

Implemented behavior

- Checklist management: centered 1280px container, compact responsive rows, unified list, case-insensitive name/description search with clear/no-results actions, enabled counts, weight, modification date, explicit backend availability, accessible overflow actions, independent inactive duplicates, activation/deactivation, and confirmed deletion. Search remains during ordinary interactions. Multiple checklists may be active. The original checklist cannot be deleted or deactivated.
- Editor: section/criterion/settings hierarchy, criteria collapsed initially, multiple expanded criteria, global expansion controls, inline names and compact score descriptions, compact keyboard-operable switches, retained N/A text, menus for duplicate/move/enable/delete, section and criterion dragging including cross-section moves, keyboard reordering, and explicit position selection. IDs and drafts survive movement. An identity guard rejects incomplete drag transactions.
- Saving: sticky toolbar, dirty state, saving state, valid-change gating, browser unload protection, Stay/Discard navigation dialog, and immutable version creation. Numeric scales retain nonuniform values and descriptions, including numeric-to-boolean-to-numeric changes across component remounts.
- Validation: separate weight and scale checks, section totals, sticky/collapsible summary, and error buttons that expand the section/criterion, scroll, and focus the field. The existing backend remains authoritative. Maximum raw scale values remain independent of criterion weights.
- Reviews: compact counters/header, approximately 30/70 queue/workspace, search/filter/sort, retained selection, original/final comparison, separate workflow and outcome labels, constrained numeric/Boolean/N/A values, independent evaluation reasoning and decision rationale, explicit decision confirmation, and completed read-only decisions with recorded metadata.
- Evidence: contextual right drawer with native dialog focus containment and Escape/close behavior, exact transcript order, system events, timestamps, stable IDs, highlighted references, surrounding context, and explicit warnings for missing references. Opening the drawer retains decision drafts. Conversation navigation carries an explicit return URL and selected appeal.
- Finalized reports/export/classification inputs consume revised values, rationale and evidence without overwriting original criterion records. Substantive review changes use the existing reclassification queue.

Additive backend contracts

- POST /api/v1/checklists/:id/status: { is_active: boolean }.
- POST /api/v1/checklists/:id/duplicate: optional { name }; returns an independent checklist/version. Duplicates start inactive.
- Checklist records add is_active. Legacy records without that field retain their existing active behavior. Summaries add enabled_criterion_count, can_delete and can_deactivate. active_version_id remains the selected immutable version even while unavailable for new evaluations.
- POST /api/v1/appeals/:id/decision additionally accepts revised_explanation and revised_evidence_message_ids. Decisions add outcome, effective_explanation and effective_evidence_message_ids. New appeal snapshots also include criterion weight and numeric-scale metadata. Historical status values remain intact.
- GET /api/v1/appeals/summary returns total/pending/completed counts.
- GET /api/v1/appeals?limit=all returns the complete queue; the existing default and numeric limit behavior remain supported.
- New evaluation/job/batch requests reject inactive checklists. Already accepted work can finish against its pinned snapshot.
- No historical migration or authentication change is required.
